# Round Template

Use this when the user is developing a proposal over repeated iterations.

End each round with one compact block in this shape:

```markdown
## Current Best Version
- Question:
- Hypothesis:
- Main path:
- Data:
- Evidence plan:

## What Improved This Round
- ...

## Main Risks
- ...

## Reflection
- ...

## Next Questions or Checks
1. ...
2. ...
3. ...

## Parking Lot
- ...
```

## Round Goals

### Round 1: Extract

Goal: turn the user's messy notes into one plausible project skeleton.

When the input is highly scattered, begin with:

- `What I Heard`
- `Logic Map`
- `What I Am Inferring`
- `Reflection`

Avoid:

- long literature summaries
- polished writing
- too many candidate projects

### Round 2: Compare

Goal: compare 2 to 3 candidate framings and recommend one lead version.

For each framing, state:

- what the question is
- why it could matter
- why it may fail
- whether the data path is real

### Round 3: Commit

Goal: lock the lead framing.

By the end of this round, the project should have:

- one main question
- one main hypothesis
- one main path
- one named data strategy
- one minimum viable first table or figure

### Round 4 and Beyond: Harden

Goal: improve the design without reopening the whole topic.

Focus on:

- variable construction
- identification
- falsifications
- interpretation
- fallback options

## Default Round Constraint

Unless the user explicitly asks for broad brainstorming, each round should narrow the design space.
