# Report what changed after feedback

[Professional communication and follow-up](../meso-professional-communication/SKILL.md) · [Related micro rule](../../micro-skills/report-on-feedback/SKILL.md)

**Use when** — Explain the disposition of several comments after work has been reviewed or revised.

**Correction behind the workflow** — A broad statement that a topic was addressed can hide an unanswered request. Group related comments while keeping every distinct ask traceable.

**Begin** — Run only after the person selects this task for the current request. A suggestion alone ends at the suggestion.

1. Extract each substantive request, preserving separate asks inside one comment. Group by topic and keep a short cross-reference to the original comment labels or order.
2. Check the current artifact or available change evidence for each ask. Say what changed and where, what was checked, or what remains open. Identify who can decide an open item when that is known.
3. Read the report back against the original comments. Restore any missing ask and correct unsupported completion claims in one pass. Leave conflicting requests visible.

**Deliver and stop** — Return a point-by-point report with unresolved items easy to find. A reporting pass ends with the report. Implementation or sending requires its own scope. This run permits one initial pass and at most one targeted correction and recheck. A further round or another workflow needs a fresh human choice.

**Stay asleep for** — Summarize a meeting that has no implementation update.
